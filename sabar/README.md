# SABAR — X Cafe Peshawar 🍕

Real-time **virtual queue + pre-order** PWA for X Cafe Pizza & Burger House.

> **# میں ہوں سب سے سستا** — Budget me best taste.

Scan the QR at the counter → get a token (A101, A102…) → live wait time → pre-order from the menu while waiting → WhatsApp share "Mera token A105 hai, 25 min baad ana" → sound + notification when your token is near → confetti when it's ready.

---

## ⚡ Quick start

```bash
npm install
npm run dev
```

Open http://localhost:5173

- Customer: scan flow → join → track
- Kitchen (staff phone/tablet): `?view=kitchen`
- Admin (menu/prices): `?view=admin`

> **No Supabase needed to try it** — the app runs in _demo mode_ with all data synced through browser `localStorage` (both tabs + the 1.2s poll keep everything in sync). Perfect for a quick look.

---

## 🗄 Real Supabase setup (5 min)

1. Create a free project at [supabase.com](https://supabase.com) (Neon-free-tier equivalent — Postgres included).
2. Open **SQL Editor** → paste `supabase/schema.sql` → Run. This creates `queues` + `menu` tables, indexes, the updated-at trigger, Realtime publication, RLS, and seeds the real X Cafe menu.
3. Create `.env.local`:

```
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR-ANON-KEY
```

4. Restart `npm run dev`. Real-time now syncs across **all devices** instantly (inside the same Supabase project).

## 🏗 Architecture

```
src/
├── lib/
│   ├── supabase.ts      # client + localStorage demo fallback (same shape)
│   ├── queue.ts         # algorithm: 7 min/order, ETA, rush, sasta meter
│   ├── sound.ts         # token-call chime + ready jingle (WebAudio, no files)
│   └── whatsapp.ts      # wa.me deep links, share token message
├── hooks/
│   └── useRealtimeData.ts  # central store: fetch + realtime sub + sound/notify
├── routes/
│   ├── CustomerApp.tsx   # scan → join → track (token, ETA, pre-order, share)
│   ├── KitchenApp.tsx    # queue list, accept/reject, status flow, rush meter
│   └── AdminApp.tsx      # menu CRUD, prices, rush logic panel
└── components/
    ├── common.tsx        # RushMeter, TokenFlip (framer-motion), StatusChip
    └── QRCanvas.tsx      # zero-dep QR canvas
supabase/schema.sql       # tables, seed, realtime, RLS
```

## 🧠 The algorithms

| Feature         | Rule                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------- |
| **Wait time**   | Each active order ahead = **7 min** → `ahead × 7`                                                       |
| **Token**       | Auto-increment: `A100 → A101 → A102…`                                                                   |
| **Rush Meter**  | 🟢 Khaali: <3 active • 🟡 Normal: ≥3 active or ≥2 in kitchen • 🔴 Full Rush: ≥6 active or ≥4 in kitchen |
| **Sasta Meter** | Wait **> 30 min** → 🎉 **10% OFF** discount badge (total auto-discounts)                                |
| **Token near**  | ≤2 people ahead → chime + browser Notification                                                          |
| **Ready**       | Ready status → jingle + confetti on customer screen                                                     |

## 🧪 PWA

Vite PWA (`vite-plugin-pwa`) → installable on Android (Chrome) & iOS (Safari "Add to Home Screen"). Icons generated by `scripts/gen-icons.mjs` (pure Node, no deps).

**Re-test icons after code changes:**

```bash
node scripts/gen-icons.mjs
```

## 🌍 Deploy (Vercel free)

```bash
npm run build
```

Vercel recognizes the Vite output automatically. Set the two env vars above in Vercel → Project → Settings → Environment Variables. Done.

**QR code:** the code on the scan screen opens `https://sabar-xcafe.vercel.app/?scan=1` — update the URL in `src/routes/CustomerApp.tsx` (`QRCanvas value` prop) to your production domain.
